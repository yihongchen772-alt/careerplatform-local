# 秋招追踪 · 本地单机版

这是 [careerplatform](https://careerplatform-coral.vercel.app) 的独立分支，专门做成不联网也能用的本地桌面 App，跟线上多用户版本完全分开维护，改一边不影响另一边。

跟线上版本比，换掉的东西：

- 数据库从 Postgres 换成 SQLite，存在你自己电脑的本地文件里
- 没有登录，打开就是你一个人的账号（`src/lib/session.ts` 里固定的本地用户）
- 简历/附件存本地文件夹（`src/lib/local-storage.ts`），不是云存储
- 没有找回密码——本来就没有密码

**AI 功能仍然需要联网**：面试攻略、模拟面试、性格测试的 AI 综合分析都要调用
Gemini/OpenAI/DeepSeek/Kimi/Claude/Qwen 之类的接口。第一次用之前去「账号设置」→
「AI 设置」的 API 管理里填一个你自己的 API Key——本地版没有共享额度。可以
同时配置多个服务商的 Key，切换哪个是"默认"（供上面这些文字类功能使用）。
DeepSeek/Kimi/Qwen 这类 OpenAI 兼容接口可以填自定义 API 地址（工作空间专属
网关或自建代理都行），不填就用各家的公共默认地址。Gemini 的免费额度按模型
分别计算，可以勾选多个型号，一个用完自动换下一个。

**模型改成下拉选了**，不用再手输模型名。列表不是写死的——写死的必然
过时：DeepSeek 原本预置的 `deepseek-chat`/`deepseek-reasoner`，实测这个
Key 真正能调的是 `deepseek-v4-flash`/`v4-pro`/`v4-flash-vision-exp`，一个
都对不上。所以每个服务商的编辑面板里都有「获取模型列表」，直接问服务商
自己的 `/models` 接口要，拿到的是这个 Key 当下真正可用的模型。没点这个
按钮之前，下拉框里预置了几个常见型号兜底，不至于空着。

**简历体检 / 岗位匹配 / AI 搜索公司信息这三个功能只能用 Gemini、Claude 或
OpenAI 的 Key**——因为要直接读简历 PDF/图片文件、或者联网搜索，DeepSeek/
Kimi/Qwen 的接口做不到这两件事。会优先用你的默认服务商（如果配的正好是
这三个之一），否则按 Gemini → Claude → OpenAI 的顺序自动用你配置了的那个，
不用单独再配一个 Gemini Key。

**邮件提醒换了实现方式**：原来是 Vercel Cron 每天定时跑，本地版没有一直
挂着的服务器，改成用你自己的邮箱账号（SMTP，Gmail/QQ/163/Outlook 都支持）
发信。触发方式只有两种：打开 App 时自动检查一次（有紧急事项才发，静默
跳过不会打扰），或者在总览页手动点"发送提醒邮件"立即发。App 不开的时候
不会有任何邮件。想要"App 关着也提醒"，用下面的「后台提醒」——那个走的是
系统通知、不是邮件。

**收件箱扫描（可选，默认关闭）**：账号设置 → 邮件提醒里勾选后，打开 App
时会顺便检查最近的新邮件（最多 20 封），用 AI 判断是不是面试邀请/笔试
通知/offer/拒信，是的话自动在"我的日程"生成一条。只读——不会修改、标记、
删除任何邮件，也不会自动改投递记录的状态。邮件标题和一小段正文会发给你
配置的 AI 服务商用来判断类型，这一步需要先配置好「AI 设置」的 Key。

**AI 助手（右下角悬浮窗）**：任意页面都能点开问，比如"这周有什么要跟进的"
"候选池里哪个岗位最值得投""这份简历怎么样"。每次提问会把个人资料、候选
池、投递记录、秋招信息库、近期待办、简历体检分这些数据整理一份摘要发给
AI，一次性给结论，不用自己一页页翻。用的是「AI 设置」里选的"默认"服务商，
没配置的话点了会提示先去配置。

**现在也能帮你落记录了**：直接跟它说人话，比如"我今天投了美团数据分析，
下周三一面"，回复下面会带操作按钮——记投递、加待办、加进候选池、更新
投递阶段、把秋招信息库的线索提上候选池，点一下才会真的写进数据库，
**不会自动执行**——问一句"要不要投字节"它不会替你决定投了。

按钮上会显示真正要写进去的日期（比如"下周五（2026-09-04）"），因为模型
确实会算错相对日期——之前吃过亏：只告诉它"今天几号星期几"不够，模型算
"下周五"能算成周日。改成直接把未来 14 天的日期和星期数都列出来给它查表
后才稳定对。同理，"更新阶段"这个操作的阶段字段在 schema 里做了严格的取值
限制（不能是任意字符串），因为共享额度常用的轻量模型有时会把自己的思考
过程也塞进这个字段，不加限制会导致更新失败（v0.3.1 修的）。

对话历史存在页面里，刷新页面会清空，不会跨设备同步。

**企业名录已预置 19 家知名企业**（字节/腾讯/阿里/华为等，`prisma/
seed-companies.js`），带真实官方招聘入口链接。添加公司时可以点"AI 搜索"，
让 AI 联网搜一下这家公司的招聘入口和行业信息自动填入——用的是 Gemini/
Claude/OpenAI 官方的搜索能力查公开网页（官网、新闻），**不会也不能爬
小红书这类需要登录的平台**（会被反爬、且违反平台条款），搜到的链接仍需
你自己核实。

**候选岗位新增"部门"字段**：AI 自动填充 JD 时会尝试识别岗位所属的具体
业务部门/事业群（跟"方向"这个技术分类是两回事），识别不到就留空，不
编造。

**秋招信息库 vs 候选岗位池**：这是两层。信息库放群里流传的那种大而全的
汇总表（几百条、大部分跟你无关），候选岗位池只放你筛完真打算投的。信息
库里勾选「加入候选池」才会流转过去，已流转的会打标记、默认从列表里隐藏，
不会重复出现。

**导入秋招信息表**（秋招信息库 → 导入信息表）：三种方式——传 Excel/CSV
文件、直接粘贴一段文字、或者传截图（手机上刷到的招聘帖直接截图即可，读图
需要 Gemini/Claude/OpenAI 的 Key）。表格列名五花八门（"公司"/
"企业名称"、截止日期写成"10.15"/"10月15日"/"长期有效"），所以不按固定列
解析，而是把行摊平成文本交给 AI 归一化：薪资统一换算成 K、日期补全成
YYYY-MM-DD（会把当天日期一起告诉 AI，否则"10.15"会被补成过去的年份）、
"长期有效"这类留空不编造。表格如果有规整表头（公司/岗位/地点/截止日期这类），走的是**直接按列映射**：
不调 AI、不截断、几千行 2 秒出结果——因为 AI 的上下文一次装不下几千行，
这种表必须先机械结构化。识别不到表头才回退给 AI 读。

按列映射忠实但不聪明：原表常把十几个岗位塞进一个格子。所以预览里有
「AI 精读整理」——勾选想要的（一次最多 40 条），让 AI 拆分混在一起的岗位、
归一化方向、清理冗余备注。实测 3 条能拆成 17 条独立岗位。

解析完先出预览让你逐条勾选，确认后才进信息库；
同公司同岗位已在库里的会自动跳过。信息库里可以按公司/岗位/部门搜索、按
城市和方向筛选、按匹配分或截止日期排序，再批量挑进候选池。

飞书/腾讯文档的表格要先在原平台「导出为 Excel/CSV」再导入——那种分享
链接需要登录，App 读不到。

预览里和信息库里都可以点「按我的简历匹配」：AI 会拿你简历（用的是「AI
体检」缓存的结果）跟这批岗位逐个比，给 0-100 匹配分和具体理由，并把高分
的排到前面。整批岗位只花一次 AI 调用，不是一个岗位调一次。

**后台提醒**（账号设置 → 后台提醒）：默认提醒只在打开 App 时检查一次，
App 没开就不提醒——这对"别错过截止日期"这个核心诉求是不够的。打开「常驻
托盘」后，关闭窗口不再退出 App 而是缩到托盘，每 30 分钟检查一次，有当天
到期或已过期的事项就弹系统通知（同一件事只提醒一次，不反复打扰）；真正
退出请用托盘菜单的「退出」。再打开「开机自动启动」就能开机后自动在托盘
里跑起来。

常驻托盘之后，收件箱扫描也能跟着定时跑（原来只在打开 App 时扫一次）。
后台提醒卡片里能选扫描频率：关闭 / 1 / 2 / 4 / 6 / 12 小时。每次扫描都要
一次 IMAP 拉信 + 一次 AI 判断邮件类型，所以没有做成跟 30 分钟提醒同一个
节奏，用单独的定时器（每 5 分钟醒一次判断够没够设定的间隔），这样调短
间隔不用等上一个周期走完。托盘菜单里也加了「立即扫描收件箱」，不用等。

这两个开关存在 userData 的 `app-settings.json` 里，而不是数据库——Electron
主进程没有 Prisma，只能读文件。开机自启是操作系统层面的操作，可能被系统
拒绝（本 App 未做代码签名，macOS/部分 Windows 策略会拦），主进程会读回
实际状态、失败时在设置页显示提示并给出手动添加的方法，而不是让开关看着
是开的却没生效。

**岗位口碑**（候选岗位池每行的「岗位口碑」）：查这个岗位的真实情况——薪资
水平、加班作息、面试难度、团队氛围、最近动态。走的是 AI 服务商自带的联网
搜索，只读公开网页（新闻、知乎、脉脉、看准，以及被搜索引擎收录的小红书
内容）。

**关于小红书**：不做直连——它没有对第三方开放的内容搜索 API（开放平台只
面向企业做电商/广告），内容在登录墙后且有请求签名反爬，硬爬要绕过技术
保护措施、违反平台条款，还会让**你自己的账号有被封风险**。

绕道搜索也不行：实测让联网搜索定向找小红书笔记，返回的是"没有搜到小红书
内容"——搜索引擎基本没收录它。

所以小红书内容的正确用法是**手动粘贴或截图**：「秋招信息库 → 导入信息表」
里的方式二（粘贴文字）和方式三（传截图）。截图那条尤其顺手——手机上刷到
直接截图就行，不用跟它的文本选择较劲，图里信息是图片形式的也照样能读。实测拿一篇典型的"26届秋招捡漏合集"笔记验证过：4 条信息里正确认出
3 个真岗位，第 4 条"某大厂运营岗（不方便说名字）"因为没有公司名被正确跳过，
日期"10月20号""11.5"都补全成了 2026 年。截图路径也用一张渲染的小红书样式
帖子验证过：3 个岗位全部正确读出，"10.28""11月10号"补对年份，"长期有效"
正确留空，部门"物流平台部"提取到位，点赞数和话题标签正确忽略。

这类信息本质是匿名爆料和个人分享，样本少、主观性强。所以结果会标一个
可信度等级（高/中/几乎没查到），查不到的维度会明确列出"没查到"而不是
用同类公司的印象凑数，末尾还有一句局限性说明。**当参考，别当事实。**
需要 Gemini/Claude/OpenAI 的 Key（要联网搜索）。

**备份与恢复**（账号设置里）：所有数据只存在本机，没有云端副本，所以提供
了导出/恢复。导出会把全部数据 + 简历文件打包成**一个** JSON 存到「下载」
文件夹（简历以 base64 内嵌，所以一个文件就是完整备份，不依赖任何压缩库）。
恢复是**破坏性**的：会清空当前数据换成备份内容，确认框里会先显示备份时间和
条目数。恢复时会跳过关联缺失的坏数据并如实报告跳过了多少条，不会因为个别
坏行就整个失败。注意备份里含加密后的 API Key，文件请自己保管好。

**投递记录加了看板视图**（投递记录页顶部切换「看板」/「列表」）：按阶段
分列展示，每张卡片显示在当前阶段停留了多少天（超两周标红），可以直接
点卡片上的箭头一键推进到下一阶段。列表原来只能回答"我投了什么"，回答不
了"我卡在哪"——十几条躺在简历筛选中，看板上一眼就看见，列表里看不出来。
投递流程也加了「测评」阶段，插在简历筛选中和笔试之间。

**状态流转时间线可以改、可以删了**：看板一键推进容易手误点错，原来的
时间线是只读的，点错了没法纠正。现在每条历史记录能改阶段、改时间、改
备注，也能单独删除（至少保留一条，删空了请直接删除整条投递）。改完或
删完都会把当前状态按剩下的最新记录重新算一遍，不会出现"当前状态"和
时间线对不上的情况。AI 模拟面试的历史记录同理，也能改名（练第二次同一
家公司容易分不清是哪场）、能删除。

**Offer 对比从卡片改成横向表格**：原来只有薪资和地点，现在加了年包、
单程通勤、加班情况、发展空间四个维度，一行一个维度、几个 offer 的数字
挨着放，不用一边看一边记"另一个通勤是多少来着"。只在明确越大/越小越好
的维度（月薪、年包、通勤）标"最优"，加班情况和发展空间是自由文本，硬给
"大小周"和"弹性但晚上盯线上"排高下没有意义，不做这个判断。

**题库**（新页面）：和某条投递解耦的题目集合，可以导入导出。导入支持
粘贴群里那种带编号的纯文本列表（"1."「2、」"-"「Q1:」这些编号会自动
识别并去掉），也支持读取导出的 JSON。导出两种格式：JSON（方便再导入）
和 Markdown（方便直接发群里）。某条投递生成的面试题库多了「存进题库」
按钮——原来生成完绑死在那条投递上，换个公司遇到类似题目还得重新生成。
导入的题库通常只有问题没有参考答案，「AI 补参考思路」只处理还没答案的
题（重跑不会重复付费），有做过体检的简历就结合真实经历给建议，没有就
退化成通用答题框架，不编造。

**题库按技术模块分组**（C++、Python、大模型、嵌入式、强化学习、具身
智能……），跟"题目类型"（项目经历/计算机基础/行为面试，AI 生成 Q&A
时自带的那个）是两个维度，互不冲突。三种打模块的方式：导入时文本里写
`# C++` 这样的标题行，下面的题目自动归到这个模块；已经导入但没打模块
的题库点「AI 分模块」批量打（只处理还没打的，重跑不重复付费，同一个
题库里已经用过的模块名会喂给 AI 当参考，不会同一个意思造出"大模型"
"LLM"两个名字）；点开题目上的模块小按钮可以手动改，AI 判断得不准的
时候一键纠正。模块不是固定枚举，是自由文本——每个人的技术方向都不一样，
写死一套分类对别的方向的人没意义。

**模拟考试**：题库卡片上的「模拟考试」进去能选考哪些模块（不选就是整个
题库）、几道题、给多少分钟，题目从选中范围里随机抽取。倒计时到点自动
交卷，答了多少交多少。交卷后 AI 一次性批量打分——空白直接 0 分，不会
因为"态度认真"放水，每题给具体反馈（答对了哪部分、漏了什么），最后还有
一句总评点出哪个模块明显薄弱、该重点复习什么（实测：C++/Python 各答两题、
故意留白两题，总分卡在两次答对题的均分附近，总评正确指出留白更多的那个
模块偏弱）。考试记录留在题库页底部，能回看每道题的作答、参考答案和反馈，
也能删除。

**资料库**（新页面）：证书、作品集、笔试资料、面试资料四个固定分类
（比自由标签更不容易散成一堆不一致的写法），加上投递记录里传过的附件
自动汇总进来。上传口子和简历上传是分开的路由——资料库要收 Word/PPT/
Excel/zip/txt，放开到简历上传口子上没有意义，单独一条 25MB 上限的路由。

**AI 模拟面试可以开口答了**：点「说」录音，说完自动转写到输入框——先
让你确认/修改再发送，转写会出错，一个错字不该直接送到面试官面前。浏览器
`MediaRecorder` 录出来是 WebM/Opus，不在 Gemini 支持的音频格式列表里，
所以在浏览器端解码后重新编码成 16kHz 单声道 WAV（实测验证过：中文语音
3 秒内准确转写），顺带把上传体积压到十分之一。除了转写文字，AI 还会
单独给一句"怎么说的"的观察（语速、流利度、口头禅、长时间停顿），结束
面试时会跟着对话记录一起进最终反馈——这是打字面试根本看不出来的部分。
需要 Gemini 的 Key，首次使用系统会弹麦克风权限请求。

## 开发模式

```bash
npm install
npm run electron:dev
```

会启动一个本地 Next.js 服务（端口 3210）并打开一个 Electron 窗口指向它。
第一次启动会自动跑数据库迁移（建表），数据存在系统的 App 数据目录里
（Mac 是 `~/Library/Application Support/秋招追踪/`）。

也可以不走 Electron，纯网页调试：`npm run dev`，用的是项目根目录下
`.env` 里配的 `file:./local.db`。

## 打包成安装包

```bash
npm run electron:build
```

产物在 `dist-electron/` 目录。

## 已知限制 / 没验证的部分

- **Windows 打包能出、但没在真机上跑过**：从 Mac 交叉编译 `.exe`（NSIS 安装包）
  已经能成功产出（修了一个 `node_modules/.bin` 里全是断链符号链接导致
  7-Zip 打包失败的问题——`.bin` 其实运行时用不上，直接从打包清单里去掉了），
  但只验证到"打得出包"，没有 Windows 机器实际装过、跑过，安装体验/运行
  是否顺畅没有第一手验证。
- **Windows 必须显式指定架构**：electron-builder 默认跟随**打包机器**的架构，
  在 Apple Silicon 的 Mac 上打出来的是 win-arm64 安装包——绝大多数 Windows
  PC（Intel/AMD）根本装不上。所以 `build.win.target` 里显式写了
  `arch: ["x64", "arm64"]`，产物文件名也带上架构后缀避免拿错。已用
  `file` 读 PE 头核对过：x64 包是 `x86-64`，arm64 包是 `Aarch64`。
- **首次启动稍慢**：第一次打开要跑数据库迁移，正常几秒内完成；如果卡住
  很久说明迁移失败了，看不到界面的话可以在终端跑 `npm run electron:dev`
  看具体报错。
- **没有自动更新机制**：以后代码改了，得重新打包、重新安装，不会自动推送更新。
- **免费版 Gemini 的联网搜索额度极少**：实测 Google 对联网搜索（Search
  grounding）单独计量，额度远小于普通调用——同一个 Key、同一时刻，普通生成
  1.3 秒正常返回，而 4 个模型做联网搜索全部 429。**换模型没用**，卡的是能力
  不是模型。所以联网搜索优先用 Qwen（阿里不单独计量），Gemini 作为备选。
- **Qwen 联网搜索不支持"抓取网页正文"**：`search_strategy: agent_max`（Web
  Extractor）在非流式调用下会被拒（实测 400 "Non-streaming mode does not
  support Web Extractor."），所以只用基础的 `enable_search`，靠搜索结果作答
  而不是抓全文。另外它比 Gemini 慢不少，实测一次约 40 秒。
- **「岗位口碑」的实际覆盖率有限**：实测拿字节的后端岗去查，Qwen 只搜到官方
  招聘页快照，没搜到爆料/面经，于是如实返回"几乎没查到"（没有拿刻板印象
  凑数，这是预期行为）。也就是说这个功能能不能给出有用信息，很依赖目标公司
  在公开网页上的讨论量，冷门岗位大概率查不到。
